# Claude implementation prompt for Tower Android

Work in the Tower repository as a senior Kotlin Compose Multiplatform and Media3 engineer. Inspect the existing playback owner, Kidoo API client, DataSource factories, Firebase endpoint repository, and tests before editing. Preserve the existing API and app navigation. Do not modify Kidoo or use a live provider for tests.

1. Give each intentional playback start one UUID. Send it as `X-Playback-Attempt-Id` on Kidoo control calls and same-origin Media3 manifest requests. Capture the returned ID for sanitized diagnostics. Never forward Kidoo bearer credentials, mirror cookies, or the diagnostic header to CDN origins or cross-origin redirects. Check the effective URI on every request.
2. Use one lifecycle owner for Media3. Coalesce duplicate starts for the same screen, content, and source. Recomposition must never initialize another player. On source or title switches, first cancel pending HTTP/resolution work and release the old player's resources on its application looper. Ignore stale async results using a local generation. Decide whether MediaSessionService or the screen owns playback so configuration changes and background controls cannot create two owners.
3. Inspect and document the current startup route. Choose the one already supported by this client. Avoid loading both `/playback/playlist` and `/playback/hls` for the same start. Keep only provider-required heartbeat behavior. Use one timer per active playback attempt, stop it at session release, and honor the existing policy for pause and background playback. Recovery from background playback must not trigger a parallel start.
4. Separate Kidoo bearer refresh from upstream authorization. Single-flight `POST /api/auth/refresh` with the current refresh token, atomically persist the rotated pair, and replay an eligible Kidoo request once. For upstream `429` or overload `503`, parse `Retry-After` as delta seconds or HTTP date. Honor the delay with bounded jitter while the attempt remains active. On `MIRROR_SESSION_REVOKED`, show the source-unavailable state and wait for an explicit retry. Never automatically retry an upstream access challenge. An expired provider URL may be replaced by one authorized master reload for the active attempt.
5. Use Firebase-discovered URL changes for new API operations. Bind an active manifest and its relative Kidoo URLs to the origin that issued it. An endpoint change alone must not restart working playback. Cancel stale work when a new origin is selected for a new attempt. Validate the configured origin before attaching credentials.
6. Add local tests for recomposition, fast taps, late request completion, player release, background transitions, cooldown and revocation handling, simultaneous JWT expiration, and origin changes during playback. Use a fake player and a loopback mock provider. Report startup and release counts and sanitized attempt logs with operation, timing and outcome. Never log media URLs, tokens, cookies, or credentials.
